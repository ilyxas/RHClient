# 0004. App Transport Security: продакшн-ядро и dev-ядро

- **Пункт:** PLAN, этап 1, `[проверить]`: сертификат `tailscale cert` проходит ATS без исключений (совместно с сервером, SPEC §3.3).
- **Этап:** 1. **Дата:** 2026-10-19.
- **Статус:** продакшн закрыт по документации, проверяется первым запросом с iPhone при приёмке этапа 1. Dev закрыт решением ниже и проверяется UI-тестами в симуляторе.

## Вопрос

1. Нужны ли исключения ATS для `https://<mac>.<tailnet>.ts.net:8443`?
2. Как Debug-сборка ходит на dev-ядро `http://127.0.0.1:8787` (SPEC §9.1)?

## Что говорит документация

- Apple, «Preventing Insecure Network Connections». ATS требует от сертификата доверенный корень, RSA ≥ 2048 или ECC ≥ 256 бит, SHA-256 и выше. От соединения: TLS 1.2+, AES-128/256, forward secrecy через ECDHE. <https://developer.apple.com/documentation/security/preventing-insecure-network-connections>
- Сервер, решение 001: сертификат от Let's Encrypt через `tailscale cert`, iOS доверяет ISRG Root X1 с iOS 10. Uvicorn поднимает TLS через Python `ssl` с настройками по умолчанию: TLS 1.2+, ECDHE, AES-GCM. (RHServer `docs/decisions/001-tailscale-cert.md`.)
- Про IP-адреса и loopback Apple писала по-разному в разные годы. Quinn (Apple DTS), июнь 2017: «On iOS 10 and later such loads [IP addresses] are always allowed» <https://developer.apple.com/forums/thread/66417>. Обсуждение 2024 года об iOS 17: для URLSession-запросов на IP-адреса нужны записи в `NSExceptionDomains` (Quinn: «you are correct that you need to add NSExceptionDomains for the IP addresses in play») <https://developer.apple.com/forums/thread/747421>.

## Решение

1. **Release:** никаких ключей `NSAppTransportSecurity`. Сертификат Let's Encrypt (ключ ECDSA P-256 или RSA 2048, ATS допускает оба) и TLS uvicorn проходят требования ATS. Если первый запрос с iPhone не пройдёт, чинить надо сервер, а не добавлять исключение (так советует и Apple).
2. **Debug:** точечное исключение только для `127.0.0.1`, `NSExceptionAllowsInsecureHTTPLoads`, в `Config/Debug-Info.plist`. Xcode подмешивает этот файл к сгенерированному Info.plist только в конфигурации Debug (`INFOPLIST_FILE`). Так dev-ядро работает при любом поведении ATS к IP-адресам. В Release ни файла, ни исключения нет. `PairingString` принимает `http` только для `127.0.0.1`, и только когда его вызывают с `allowLocalHTTP` (в Debug).
