# RHClient — правила для агентов-разработчиков

iOS-приложение RemoteHands: SwiftUI, iOS 27, Swift 6. Что строим — SPEC.md проекта RemoteHands; как работаем — PROCESS.md; план и решения владельца — `PLAN.md`.

## Структура

- `RHClient/` — приложение. Папка синхронизируется с Xcode: новый файл подхватывается сам, `project.pbxproj` руками не править без нужды.
- `Packages/RHKit/` — логика без UI (JCS, ключи и подписи, API, модели, страницы). Тесты: `swift test --package-path Packages/RHKit`.
- `RHClientTests/`, `RHClientUITests/` — тесты приложения (Swift Testing; UI — XCTest).
- `contracts/` — **копия** `contracts/` из RHServer. Не редактировать. Обновлять только `scripts/sync-contracts.sh <sha>` отдельным коммитом «sync contracts @<sha>». Изменение контракта — PR в RHServer, ревьюит агент iOS.
- `docs/decisions/` — закрытые `[проверить]`: вопрос, вывод, источник, дата.

## Как проверять

- Без Mac (Linux): `python3 scripts/check_project.py` (структура Xcode-проекта), `scripts/check-contracts.sh` (копия контрактов совпадает с RHServer).
- На Mac (Xcode 27): `scripts/test.sh` — всё сразу: контракты, `swift test` для RHKit, `xcodebuild test` в симуляторе. Для UI-теста pairing скрипт поднимает dev-ядро из `../RHServer` (`RH_SERVER_DIR`), сбрасывает Keychain симулятора и отвечает на Face ID «совпадающим лицом».
- Тест-векторы из `contracts/vectors/` обязательны: если вектор не проходит, ошибка у нас, пока не доказано обратное с агентом сервера.

## Правила

- Решения SPEC §1–4 и §7.1 не менять без владельца. Не добавлять ограничений и подтверждений сверх SPEC.
- Уровень ключа проверяет сервер. Клиент выбирает ключ по `x-rh-key` операции и подписывает то, что показывает.
- Клиент отвергает ответ ядра без валидной `X-RH-Server-Sig`.
- Тестовые швы только в Debug (`#if DEBUG`): `SoftwareKeyProvider`, pairing-строка из буфера обмена или `-RHPairing`, `http://127.0.0.1:8787`. В Release их нет.
- Сторонние библиотеки — только после утверждения владельцем (Markdown — этап 3, SSH и терминал — этап 6).
- Каждое `[проверить]` закрыть записью в `docs/decisions/` до реализации части, которая от него зависит. Если факт расходится со SPEC — остановиться и спросить владельца.
- Один PR — один этап (или его логичная часть). Описание: Before / After / How, что не менялось, что не проверено.
- Репозитории публичные. В код, коммиты, PR, комментарии и `docs/decisions/` не попадают IP-адреса, имена хостов, устройств и людей, email, Team ID, пути с именем пользователя и прочие данные с Mac владельца или из его сети. Вместо них плейсхолдеры (`100.x.y.z`, `<mac-name>`, `~/…`) и фикстуры. Team ID — только в `Config/Local.xcconfig` (не коммитится).
